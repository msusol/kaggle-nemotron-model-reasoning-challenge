## 1. HF→Megatron checkpoint save OOM and cascading failures

### Context

The `MegatronPolicyWorker.__init__()` performs a one-time conversion of the HuggingFace checkpoint to Megatron format on first run. It saves the result to `.cache/huggingface/nemo_rl/<model>/iter_0000000/`. On subsequent runs it detects the existing directory and skips conversion. The conversion + save is the dominant memory event at startup.

Model: `nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16` (~54 GB BF16)

### Findings

**Memory budget on GB10:**
- Physical unified HBM: 121 GB
- Default swap (`/swap.img`): 15–16 GB
- Peak demand during save: active_anon ~18 GB + inactive_anon ~39 GB (freed HF pages) + shmem ~54 GB (CUDA model) + CPU copy for save ~54 GB = ~165 GB
- Shortfall without extra swap: ~44 GB

**Correct Megatron module:** `megatron.bridge.training.checkpointing` (NOT `megatron.training.checkpointing`). The save path is `megatron.bridge.training.model_load_save.save_megatron_model` → `megatron.bridge.training.checkpointing.save_checkpoint`. Uses `dist_checkpointing.save()`, not raw `torch.save`.

**`pt_checkpoint_exists` check** (`megatron_policy_worker.py:588`):
```python
pt_checkpoint_exists = os.path.exists(pretrained_path) and os.path.exists(
    os.path.join(pretrained_path, "iter_0000000")
)
```
Only checks that the directory exists — does NOT verify completeness. A partial checkpoint (even a single `common.pt`) triggers `pt_checkpoint_exists = True` and skips the conversion entirely.

**Post-skip failure:** After skipping conversion, the worker checks for `iter_0000000/run_config.yaml`. If the checkpoint is incomplete, `run_config.yaml` is absent → `FileNotFoundError` → exit 255.

**Full required flow:** convert → `save_checkpoint` (writes `common.pt` + model tensors + `run_config.yaml`) → `destroy_model_parallel` → check `run_config.yaml` → reload weights from saved checkpoint → begin training. Cannot skip the save without breaking the reload.

**`async_save` default:** The Megatron Bridge `save_checkpoint` supports async save and fully-parallel save. Defaults appear to be False, but were not explicitly set to False in our config prior to smoke15.

**Double-tee log problem:** Running `bash run_nemo_grpo_spark.sh 2>&1 | tee smoke14.log` from the shell combined with the script's internal `docker run ... | tee "${LOG_FILE}"` caused the inner tee to truncate the file, losing pre-container setup messages. Fixed by changing inner tee to `tee -a`.

### Resolution

**Status:** Unresolved — smoke15 in progress.

1. OOM during save (smoke9–11): extra 75 GB swap added; first real test is smoke15
2. Wrong Megatron module in patcher (smoke10): fixed
3. Skip-save-breaks-reload (smoke11): skip approach abandoned; full save required

5. Partial checkpoint silently triggers FileNotFoundError (smoke13–14): partial checkpoint deleted
