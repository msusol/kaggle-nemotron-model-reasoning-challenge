# v0.5 NeMo Framework Plan

## Goal

**Optional alternative training path** — run the same v0.5 dataset through NVIDIA's
NeMo framework instead of TRL SFTTrainer. This is a follow-on experiment to run
*after* the primary v0.5 TRL SFT run completes and scores.

Primary v0.5 path (run first): `scripts/train_v5_sft.py` (TRL SFTTrainer, v27 warmstart,
240 steps, competition CSV + synthetic data). See `docs/plans/v0.5-sft-kuangyicheng-plan.md`.

This NeMo path uses identical data and hyperparameters but substitutes NeMo's training
infrastructure for TRL, allowing comparison of convergence quality and throughput.

## Context

- **Status**: Optional — pending results from primary v0.5 TRL run.
- **Dataset change**: Previous NeMo dataset (`gdataranger/huikang-nemotron-nemo-sft-r32`)
  contained huikang's 0.85 long-CoT corpus — wrong format for competition scoring.
  New dataset `gdataranger/nemotron-v5-competition-nemo-sft` will be regenerated from
  v0.5 data (competition CSV + synthetic, short responses).
  See `docs/investigate/v0.4r3-training-data-alignment.md`.
- **Warmstart**: `huikang/nemotron-adapter/Transformers/default/27` (v27, 1.5 GB, public).
- **Why NeMo over TRL**: NeMo's `activations_checkpoint_granularity: selective` avoids
  the custom `_set_gradient_checkpointing()` hack required by TRL, and may give better
  throughput on long-context training.
- **Full workspace docs**: `docs/plans/nemotron_dgx_workspace/` (steps 1–5 + issues).

## v0.5 training data format

**Source**: `data/v0.5_train.jsonl` — generated by `scripts/prepare_v5_sft_data.py`
(competition `train.csv` 9,500 rows + 12,000 synthetic = ~21,500 total).

**Prompt format** (matches 0.87 notebook exactly):
```
<competition_prompt>
Please put your final answer inside \boxed{}.
```

**Response format** (short — one sentence, no `<think>` tags):
```
I identify one rule that matches all examples, verify that the same rule is consistent
across the prompt, then apply it to the target. Final answer: \boxed{<answer>}.
```

**System prompt**: `""` (empty throughout).

config must match to continue training from the same parameter space.

## Dataset regeneration

```bash
# 1. Generate v0.5 JSONL
python scripts/prepare_v5_sft_data.py \
  --train-csv data/train.csv \
  --out data/v0.5_train.jsonl

# 2. Tokenize to NeMo format (inside nemotron-gb10 container)
bash scripts/run_convert_jsonl_to_nemo.sh \
  --train data/v0.5_train.jsonl \
  --out-train data/nemo_dataset/nemo_v5_train.jsonl

# 3. Delete old dataset
kaggle datasets delete gdataranger/huikang-nemotron-nemo-sft-r32 -y

# 4. Create new dataset (gdataranger/nemotron-v5-competition-nemo-sft)
kaggle datasets create -p data/nemo_dataset
```

## Known issues

See `docs/plans/nemotron_dgx_workspace/05_NEMOTRON_FRAMEWORK_ISSUES.md`. Key constraints:

- **4-bit / 8-bit quantization**: broken — MoE expert tensors cause BitsAndBytes shape mismatches.
- **`trust_remote_code=True`**: avoid — overrides the native KV-cache fix in `transformers>=5.5.3`.
- **HF `gradient_checkpointing_enable()`**: not supported — use NeMo's selective GC.

## Post-training: convert to HF PEFT format

```bash
python /opt/NeMo/scripts/checkpoint_converters/convert_nemo_to_hf_lora.py \
    --input_nemo_file /data/nemotron_runs/.../checkpoints/last.nemo \
    --output_hf_directory /data/nemotron_hf_lora/
```

Then submit via `scripts/package_submission.sh`.

## Decision gate

Run this NeMo path **after** v0.5 TRL SFT completes and Kaggle score is known.
Primary trigger: time permits after v0.5 TRL. Secondary triggers:
- v0.5 TRL score below target — compare whether NeMo produces different quality on
  identical data
- TRL throughput too slow — NeMo's selective GC may give faster iteration

Even if v0.5 TRL scores at 0.85+, this is a worthwhile experiment: NeMo's training
stack is NVIDIA's reference implementation and may produce a marginally stronger adapter
or converge in fewer steps. Run it as a comparison whenever GB10 is available.
