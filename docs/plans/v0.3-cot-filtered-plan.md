## Why v0.2-cot Regressed

v0.2-cot used the `kienngx` peer CoT dataset unfiltered (8,358 examples). Two root causes
identified from the training comparison plot and competition notebook analysis:

1. **Noisy CoT traces** — many Gemini outputs were degenerate/incoherent yet passed the
   `>20 char` filter. The model learned to produce rambling text rather than focused reasoning.
2. **Learning rate too high** — `lr=2e-4` caused large gradient norm spikes throughout training
   (visible in `docs/images/training_comparison_v01_v02.png`). CoT responses are ~25× longer
   than bare labels; a high LR destabilises training on longer, more complex targets.

## Reference Notebook

`docs/plans/nemotron-sft-reasoning-trajectories-dataset.ipynb`
(source: `https://www.kaggle.com/code/impooping/nemotron-sft-reasoning-trajectories-dataset`)

## Dataset

**Source:** `kishanvavdara/nemotron-reasoning-traj` (Kaggle dataset)
**File:** `nemotron_traj.csv`

| Column | Content |
|---|---|
| `id` | Example ID |
| `prompt` | Competition problem text |
| `generated_cot` | CoT reasoning trace |
| `answer` | Ground-truth answer |
| `generated answer` | LLM's extracted answer |
| `correctness` | `"true"` / `"false"` — rule-based match |
| `problem type` | Category label |

**Filtering:** keep only rows where `correctness == "true"` → **4,423 verified-correct samples**

**Type-balanced sampling** (matches reference notebook):

| Problem Type | Available | Sample |
|---|---:|---:|
| Numeral Conversion | ~1,511 | 700 |
| Gravitational Constant | ~935 | 600 |
| Unit Conversion | ~1,188 | 700 |
| Text Encryption | ~483 | all (~483) |
| Bit Manipulation | ~128 | all (~128) |
| Equation Transformation | ~178 | all (~178) |
| **Total** | **~4,423** | **~2,789** |

Hard categories (Bit Manipulation, Equation Transformation) have low pass rates so all
correct samples are used.

## Response Format

The Nemotron-3-Nano model uses `<think>...</think>` tags internally. Align training targets:

```
{cot_cleaned}\n</think>\n\boxed{answer}
```

The chat template auto-prepends `<think>\n` for the assistant turn, so the assistant content
starts with the CoT directly.

Also add the official competition prompt suffix:
```
\nPlease put your final answer inside `\boxed{}`. For example: `\boxed{your answer}`
```

## Key Hyperparameter Changes vs v0.2-cot

| Parameter | v0.2-cot | v0.3 | Reason |
|---|---|---|---|
| `learning_rate` | `2e-4` | `1e-5` | Eliminate gradient spikes from long CoT targets |
| `num_train_epochs` | 1 | 2 | More signal from smaller filtered dataset |
| `max_seq_length` | 2048 | 4096 | CoT traces can exceed 2048 tokens |
| `target_modules` | `all-linear` | `in_proj\|out_proj\|up_proj\|down_proj` | Matches competition starter template |
| `lora_alpha` | 64 | 32 | Match reference notebook |
| `warmup_ratio` | 0.03 | 0.1 | Longer warmup for lower LR |
| `per_device_train_batch_size` | 1 | 1 | GB10 constraint |
| `gradient_accumulation_steps` | 8 | 16 | Larger effective batch for stability |
| `gradient_checkpointing` | False | False | NemotronH doesn't declare support |
| Response format | `Final answer: \boxed{}` | `</think>\n\boxed{}` | Aligns with model pre-training |

## Steps

### Step 1 — Download `kishanvavdara/nemotron-reasoning-traj`

Write `scripts/download_cot_filtered.py` using `kagglehub.dataset_download`:

```python
kagglehub.dataset_download("kishanvavdara/nemotron-reasoning-traj")
```

Inspect schema, confirm `correctness` column, filter and sample per table above.

### Step 2 — Convert to JSONL

Apply the `</think>` response format:

```python
cot_cleaned = re.sub(r'\\boxed\{[^}]*\}', '', row['generated_cot']).rstrip()
user_content = row['prompt'] + PROMPT_SUFFIX
assistant_content = cot_cleaned + f"\n</think>\n\\boxed{{{row['answer']}}}"
```

Output `data/train.jsonl`, `data/valid.jsonl`, `data/valid_labels.jsonl` (90/10 split).

### Step 3 — Update `configs/nemotron.yaml`

```yaml
learning_rate: 1e-5
num_epochs: 2
max_seq_length: 4096
lora_alpha: 32
```

### Step 4 — Update `train_lora.py` LoRA target modules

Change `target_modules` from `"all-linear"` to:
```python
target_modules=r".*\.(in_proj|out_proj|up_proj|down_proj)$"
```

Note: this is a regex string, not a list — `LoraConfig` accepts regex patterns.

### Step 5 — Run training

```bash
RUN_NAME=cot_v3 bash scripts/run_train.sh
```

### Step 6 — Validate and submit

```bash
bash scripts/run_inference.sh
bash scripts/run_validate.sh --predictions output/predictions_cot_v3_YYYYMMDD_HHMMSS.jsonl
bash scripts/package_submission.sh output/adapter_cot_v3_YYYYMMDD_HHMMSS
```

## Why We Stopped

v0.3 scored 0.50 on Kaggle — a second consecutive regression (v0.1=0.57 → v0.2=0.54 → v0.3=0.50).
Local validation (v0.3 valid set inference) was halted mid-run (35/279 examples) because the
Kaggle score made further local analysis moot.

**Root causes confirmed:**
1. **Data scope** — kishanvavdara covers only 2,510 of 9,500 training problems; the 6,990
   gap problems (disproportionately `bit_manipulation` and `algebra`) receive no CoT training
2. **Data quality** — CoT traces (~500 tok average) are too short; the 0.85 notebook uses
   exhaustive hypothesis-testing traces averaging ~3,292 tokens
3. **Missing test set** — kishanvavdara only covers training problems; the evaluation (Kaggle)
   runs on the full test set including unseen problem types

**Pivot:** v0.4 uses `samvalladares/huikang-nemotron-artifacts` — a public corpus covering
15,979 problems (training + test set) with exhaustive long-form CoT. See `v0.4-blended-plan.md`.
