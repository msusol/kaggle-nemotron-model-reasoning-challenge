# v0.4 Kaggle Regression — Root Cause Analysis

| Run | Score | Notes |
|---|---|---|
| v0.1-baseline | 0.57 | Raw competition data, 6 categories only |
| v0.4-huikang | 0.49 | System prompt mismatch + \boxed{–} placeholder |
| v0.4-huikang-r2 | 0.50 | Fix 1+2 applied; new root cause exposed (see §3 below) |

**Eval token accuracy**: 94.47–94.57% across both v0.4 runs — high on training
distribution, but Kaggle score regresses vs the 0.57 baseline.

## Root causes

### 1. System prompt mismatch (primary)

The huikang corpus has `"system": ""` (empty string) for all examples.
`format_example` uses `example.get("system", default)` — because the key *exists*
with an empty value, Python returns `""` not the default. So training saw:

```
system: (empty)
user:   <problem>
assistant: <think>
...reasoning...
</think>
\boxed{answer}
```

But `infer_lora.py` injects:

```
system: You are a careful reasoning model. Solve the problem step by step and end with Final answer: \boxed{...}.
```

This system prompt is **out-of-distribution** — the model never saw it during training.
It likely causes the model to switch generation style, producing the baseline-style
`Final answer: \boxed{...}` format instead of the `<think>...</think>\boxed{}` format
it was trained on, corrupting both the reasoning chain and the final answer.

### 2. `\boxed{–}` placeholder in thinking chain

Huikang responses contain a placeholder before the real answer:

```
The answer in \boxed{–} is \boxed{00110100}
</think>
\boxed{00110100}
```

If the competition's scorer extracts the **first** `\boxed{}` from the model output,
it gets `–` instead of the answer. Our local `validate_metric.py` already uses
`boxed[-1]` (last), so local scores are unaffected. Kaggle's scorer behaviour is
unknown — this may or may not compound the issue.

### 3. System prompt contradicts augmenter category responses (v0.4-r2, new)

Fix 1 injected `system: "Solve the problem step by step. Put your final answer in \boxed{}."`.
This fixed the train/infer mismatch for the 9 boxed categories — but created a new
contradiction for 8,046 rows (~53% of training data) across the 5 augmenter categories
(`matching`, `splitting`, `concatenation`, `spelling`, `lstrip`):

```
system:   "Solve the problem step by step. Put your final answer in \boxed{}."
response: <think>
          ...structured reasoning...
          Best: 3 4 5 6 7 0 1 2: 8
          </think>
          ← NO \boxed{} here
```

The model learned conflicting behaviour: output `\boxed{answer}` for bit_manipulation/
cipher/etc., but NOT for matching/splitting/etc. At Kaggle inference time, ~53% of
test problems receive no boxed answer → scorer returns 0 for those categories.

**Why this explains 0.50**: if 47% of test problems score near-perfectly and 53% score
0%, the expected total is `0.47 × ~1.0 ≈ 0.50` — exactly what we observe.

**Why the 0.87 notebook avoids this**: it trains with `system: ""` throughout. The
`\boxed{}` instruction lives in the user prompt text for the 9 boxed categories; the 5
augmenter categories never show `\boxed{}` in prompt OR response, so there is no
contradiction. The Kaggle scorer handles those categories' structured non-boxed output.

## Fix for next v0.4 re-run

**Status of each fix:**

| Fix | Status | File |
|---|---|---|
| Fix 1 — `get("system") or SYSTEM_PROMPT` | ✅ Applied (v0.4-r2) | `train_lora.py:95` |
| Fix 2 — Match system prompt in `infer_lora.py` | ✅ Applied (v0.4-r2) | `infer_lora.py` |
| Fix 3 — Strip `\boxed{–}` placeholder | ⚠️ Not yet applied | `extract_huikang_corpus.py` |
| Fix 4 — Resolve system prompt / augmenter contradiction | ⚠️ Not yet applied | `train_lora.py` |

### Fix 3 — Strip `\boxed{–}` placeholder from training responses

In `scripts/extract_huikang_corpus.py` `parse_unmasked()`, strip the Tinker template
line so only the clean answer remains inside `<think>`:

```python
# In parse_unmasked(), after stripping <|im_end|>:
import re
text = re.sub(r"The answer in \\boxed\{[–-]\} is ", "", text)
```

### Fix 4 — Resolve system prompt / augmenter contradiction

**Option A (recommended): drop system prompt — match 0.87 approach**

Set `system = ""` in `format_example` for all rows. The `\boxed{}` instruction is
already in the user prompt for the 9 boxed categories; no system prompt needed.
Augmenter categories produce non-boxed structured output as trained.

```python
# train_lora.py format_example — revert fix 1:
system = example.get("system")  # always "" for huikang corpus
```

Also update `infer_lora.py` to pass `system=""` at inference time.

**Option B: add `\boxed{answer}` to augmenter responses on re-extraction**

Post-process augmenter category responses in `extract_huikang_corpus.py` to append
`\n\boxed{<extracted_answer>}` after `</think>`. Requires parsing the correct answer
from each category's reasoning chain:

| Category | Answer location in response |
|---|---|
| `matching` | Last `Best: <sequence>: N` line — extract `<sequence>` |
| `splitting` | Full split table — unlikely to fit cleanly in `\boxed{}` |
| `concatenation` | Last output line |
| `spelling` | Last output line |
| `lstrip` | Last output line |

Option B is complex for `splitting` (multi-line answer) and adds risk of extraction
errors. **Option A is lower risk and matches the proven 0.87 approach.**

### Re-extraction and retrain checklist

If proceeding with a v0.4-r3 SFT run, apply in order:

- [ ] Apply Fix 3 in `extract_huikang_corpus.py` — strip `\boxed{–}` pattern
- [ ] Apply Fix 4 Option A in `train_lora.py` — set `system = example.get("system")`
- [ ] Apply Fix 4 Option A in `infer_lora.py` — set `system = ""`
- [ ] Re-run extraction: `bash scripts/run_extract_corpus.sh`
- [ ] Verify: spot-check 5 rows per category — confirm no `\boxed{–}`, correct system field
- [ ] Retrain: `RUN_NAME=huikang_v4r3 bash scripts/run_train.sh`
- [ ] Submit and record in leaderboard

## Impact on v0.5 GRPO

v0.5 GRPO init from `adapter_huikang_v26` (kuangyicheng's 0.85 adapter) sidesteps all
four issues — v26 was trained with the correct empty-system format and already handles
all 14 categories correctly. GRPO rewards correct answers directly, so format problems
self-correct over training. Fix 3 and Fix 4 still apply if running a fresh v0.4 SFT
re-run as an alternative path.
