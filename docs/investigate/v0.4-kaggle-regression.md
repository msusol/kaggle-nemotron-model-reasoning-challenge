# v0.4 Kaggle Regression — Root Cause Analysis

**Score**: 0.49 (v0.4-huikang) vs 0.57 (v0.1-baseline, no CoT)
**Eval token accuracy**: 94.47% — high on training distribution, but Kaggle score regressed.

## Root causes

### 1. System prompt mismatch (primary)

The huikang corpus has `"system": ""` (empty string) for all examples.
`format_example` uses `example.get("system", default)` — because the key *exists*
with an empty value, Python returns `""` not the default. So training saw:

```
system: (empty)
user:   <problem>
assistant: <think>
...reasoning...
</think>
\boxed{answer}
```

But `infer_lora.py` injects:

```
system: You are a careful reasoning model. Solve the problem step by step and end with Final answer: \boxed{...}.
```

This system prompt is **out-of-distribution** — the model never saw it during training.
It likely causes the model to switch generation style, producing the baseline-style
`Final answer: \boxed{...}` format instead of the `<think>...</think>\boxed{}` format
it was trained on, corrupting both the reasoning chain and the final answer.

### 2. `\boxed{–}` placeholder in thinking chain

Huikang responses contain a placeholder before the real answer:

```
The answer in \boxed{–} is \boxed{00110100}
</think>
\boxed{00110100}
```

If the competition's scorer extracts the **first** `\boxed{}` from the model output,
it gets `–` instead of the answer. Our local `validate_metric.py` already uses
`boxed[-1]` (last), so local scores are unaffected. Kaggle's scorer behaviour is
unknown — this may or may not compound the issue.

## Fix for next run

### Fix 1 — Override empty system prompt in `format_example`

```python
system = example.get("system") or \
    "Solve the problem step by step. Put the final answer in \\boxed{}."
```

The `or` operator replaces falsy values (including `""`) with the default, ensuring
training and inference use the same non-empty system prompt.

### Fix 2 — Match system prompt in `infer_lora.py`

Update `infer_lora.py` to use the same system prompt as training, or read it from
`configs/nemotron.yaml` so there is a single source of truth.

### Fix 3 — Strip `\boxed{–}` placeholder from training responses

In `scripts/extract_huikang_corpus.py`, post-process responses to remove the
`The answer in \boxed{–} is` pattern, leaving only the correct `\boxed{answer}`
inside `<think>` and the final `\boxed{answer}` after `</think>`.

## Impact on v0.5

Apply all three fixes before the v0.5 GRPO run. If using v0.4 adapter as the GRPO
init point, consider doing a short SFT re-run with corrected data first.
