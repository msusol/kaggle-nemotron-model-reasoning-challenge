## 2. Response format mismatch — long CoT vs short direct answer

### Context

After pulling the 0.87 notebook source, we compared the training data format used by
kuangyicheng against what we trained on (huikang long CoT).

### Findings

**kuangyicheng training response format** (SHORT — one sentence):

```
I identify one rule that matches all examples, verify that the same rule is consistent
across the prompt, then apply it to the target. Final answer: \boxed{10010111}.
```

**Our training response format** (huikang long CoT — WHAT WE TRAINED ON):

```
<think>
We need to deduce the transformation by matching the example outputs.
I will put my final answer inside \boxed{}.

Output 0: 11011101
0 1
1 1
...
[3,000+ tokens of systematic hypothesis search]
...
I will now return the answer in \boxed{}
</think>
\boxed{10010111}
```

Kaggle's competition runner has a fixed `max_new_tokens` limit. A model trained on
3,000-token reasoning chains attempts to generate thousands of tokens before reaching
`\boxed{}`. It likely hits the token limit mid-chain and never outputs the answer.
Alternatively, the model learned the explicit `\boxed{}` instruction in the user
prompt as a trigger — absent at eval time — and doesn't output boxed format.

### Resolution

**Resolved.** The huikang long-CoT format is incompatible with Kaggle's evaluation
runner. kuangyicheng's short-response format is what works.

## 3. Prompt format mismatch — `\boxed{}` instruction added in training, absent at eval

### Context

The huikang corpus (for 9 boxed categories) adds a `\boxed{}` instruction to user
prompts. The competition eval prompts do not have this instruction.

### Findings

**huikang training prompt** (9 boxed categories):
```
In Alice's Wonderland, a secret bit manipulation rule transforms 8-bit binary numbers.
[...examples...]
Now, determine the output for: 00110100
Please put your final answer inside `\boxed{}`. For example: `\boxed{your answer}`
```

**Competition eval prompt** (`train.csv` / `test.csv` — what Kaggle's runner sends):
```
In Alice's Wonderland, a secret bit manipulation rule transforms 8-bit binary numbers.
[...examples...]
Now, determine the output for: 00110100
```

**huikang training prompt** (5 augmenter categories — no instruction):
```
In Alice's Wonderland, secret processing rules are used on text.
[...matching/splitting/etc. examples...]
[problem statement]
```

Summary across all categories:

| Category group | Training prompt suffix | Training response has `\boxed{}`? | Eval prompt suffix | Eval output? |
|---|---|---|---|---|
| 9 boxed cats | `Please put your final answer inside \`\boxed{}\`` | ✅ after `</think>` | (none) | ❓ model needs instruction? |
| 5 augmenter cats | (none) | ❌ never | (none) | ❌ nothing to extract |

### Resolution

**Resolved.** The huikang corpus prompt format was never aligned to what Kaggle's
runner sends. Only the augmenter categories matter much since the boxed categories
might still work (model may output boxed regardless), but the augmenter categories
score 0 in all runs.

## 4. The correct approach — kuangyicheng's method (v0.5 plan)

### Findings from 0.87 notebook source

Training data:
- `data/train.csv` (9,500 examples, 6 known categories) with short responses
- 12,000 synthetic examples (2,400 each × bit, cipher, unit, numeral, equation)
- **No huikang artifacts. No augmenter category training data.**
  Coverage for augmenter categories comes entirely from the v27 warmstart.

Correct prompt format:

```python
PROMPT_SUFFIX = '\nPlease put your final answer inside \\boxed{}.'

user_prompt = competition_prompt + PROMPT_SUFFIX
assistant_response = (
    'I identify one rule that matches all examples, verify that the same rule '
    'is consistent across the prompt, then apply it to the target. '
    f'Final answer: \\boxed{{{answer}}}.'
)
```

Training config:
- max_steps=240, lr=2e-4, linear LR, warmup_steps=0
- max_seq_length=6144, batch=1, grad_accum=16
- Stratified batching across category buckets
- Warmstart: `PeftModel.from_pretrained(model, huikang_v27_dir, is_trainable=True)`
- LoRA params cast to fp32 after loading
