# v0.12 Plan — Reasoner-Augmented SFT on DGX Spark

**Status**: planned  
**Hardware**: DGX Spark (GB10, 130.7 GB HBM)  
**Target score**: >0.60  
**Deadline**: 2026-06-15

---

## Motivation

GRPO on Spark (v0.11) is blocked on a startup OOM during HF→Megatron conversion.
5 days remain before the competition closes — not enough time to resolve v0.11 reliably.

The huikang corpus (which powers the 0.85 leaderboard leader) comes from deterministic
algorithmic solvers in `nemotron-master/reasoners/` and `nemotron-master/augmenters/`.
These are publicly available in `huikang/huikang-nemotron-repository-snapshot` on Kaggle.

The augmenters can generate **unlimited new problems** for all 16 categories, each
with a correct CoT trace — no LLM, no GRPO, no vLLM required. Spark's HBM has no
Kaggle quota limit, allowing longer training than the ~4.5h RTX Pro 6000 window.

## Architecture

```
huikang/huikang-nemotron-repository-snapshot
  └── augmenters/matching.py, splitting.py, concatenation.py, ...  ← generate new problems
  └── reasoners/bit_manipulation.py, cipher.py, gravity.py, ...    ← solve + narrate CoT

scripts/generate_reasoner_data.py  (NEW)
  → data/v0.12_augmented.jsonl  (new problems + traces, Format 4)

mix with data/v0.9_grpo_train.jsonl
  → data/v0.12_train.jsonl  (~25,000 rows)

scripts/train_v9_sft.py
  --warmstart-adapter  best Kaggle adapter (run7 or run4)
  → output/adapter_v12_spark/
```

## Key Design Decisions

**Augmenter-only, not reasoner-only**: The reasoners solve *existing* competition
problems (already in the huikang corpus). The augmenters generate *new* problems with
known answers. For v0.12 we use augmenters to add fresh examples, especially for the
8 test-only categories that currently have 571–1,500 examples each in v0.9 data.

**Target: 3,000 new examples per under-represented category** to balance the distribution:

| Category | v0.9 count | Target additional |
|---|---|---|
| `equation_numeric_deduce` | 573 | +2,427 → 3,000 |
| `spelling` | 571 | +2,429 → 3,000 |
| `lstrip` | 240 | +2,760 → 3,000 |
| `cryptarithm_deduce` | 97 | +2,903 → 3,000 |
| `equation_numeric` | 168 | +2,832 → 3,000 |
| `equation_symbolic` | 1 | skip (no augmenter) |
| Already well-covered (≥1,000) | — | no additional |

**Warmstart priority**:
1. run7 adapter (if training completes before Spark run starts)
2. run4 adapter (0.56, stable, 140 keys — better than run6 at 0.53)

**Sequence length**: `MAX_SEQ_LENGTH=8192` on Spark (no 9-hour quota limit).
Huikang traces are typically 2,000–7,000 tokens; the full seq range is trainable on Spark.

## Tasks

### Phase A — Get the reasoner source

- [ ] Download `huikang/huikang-nemotron-repository-snapshot` to `/workspace/huikang-repo/`:
  ```zsh
  kaggle datasets download \
    huikang/huikang-nemotron-repository-snapshot \
    --path /workspace/huikang-repo \
    --unzip
  ```
- [ ] Locate `reasoning.py` entry point and `augmenters/` directory
- [ ] Verify the augmenter interface: `augmenters/<category>.py` → `generate_problem()` or equivalent

### Phase B — Write generation script

- [ ] Write `scripts/generate_reasoner_data.py`:
  - Calls each augmenter to generate N new problems per category
  - Passes each problem through the matching reasoner to get the CoT trace
  - Filters to `status == 'rule_found'` only (skip unsolved)
  - Writes Format 4 JSONL: `assistant = {trace}\n</think>\n\boxed{answer}`
  - Accepts `--categories`, `--n-per-cat`, `--out` arguments
  - Resumes from partial output if interrupted

### Phase C — Generate data

- [ ] Run generation for under-represented categories:
  ```zsh
  python scripts/generate_reasoner_data.py \
    --repo-root /workspace/huikang-repo \
    --categories equation_numeric_deduce spelling lstrip cryptarithm_deduce equation_numeric \
    --n-per-cat 3000 \
    --out data/v0.12_augmented.jsonl
  ```
- [ ] Verify: inspect 5 samples per category, confirm Format 4 structure and correct answers
- [ ] Mix with existing data → `data/v0.12_train.jsonl`:
  ```zsh
  cat data/v0.9_grpo_train.jsonl data/v0.12_augmented.jsonl | \
    python scripts/shuffle_jsonl.py > data/v0.12_train.jsonl
  ```

### Phase D — Download best Kaggle warmstart

- [ ] After run7 completes: download `adapter_v9_run7.zip` from Kaggle output panel
- [ ] Fallback: use run4 adapter (already in `~/Downloads/adapter_v9_kaggle_run4.zip` or re-download)
- [ ] Extract to `/workspace/warmstart/`

### Phase E — Train on Spark

- [ ] In tmux on DGX Spark:
  ```zsh
  tmux new -s spark_v12
  python scripts/train_v9_sft.py \
    --model nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B-BF16 \
    --train-data data/v0.12_train.jsonl \
    --output-dir output/adapter_v12_spark \
    --warmstart-adapter /workspace/warmstart \
    --max-seq-length 8192 \
    --max-steps 600 \
    --learning-rate 1e-4 \
    --batch-size 1 \
    --grad-accum 16
  ```
- [ ] Monitor: loss should start near v0.9 SFT loss (not from scratch)
- [ ] Save checkpoint every 100 steps (add `--save-steps 100` if supported)

### Phase F — Submit

- [ ] Package adapter: `bash scripts/package_submission.sh output/adapter_v12_spark /tmp/submission_v12`
- [ ] Check daily submission limit, then submit
- [ ] Update `docs/plans/leaderboard.md`

## Open Questions

1. **Augmenter API** — the exact interface of `augmenters/*.py` needs to be verified.
   Some augmenters may require seed problems from the competition dataset rather than
   generating fully from scratch.

2. **train_v9_sft.py `--save-steps`** — check if this flag exists; if not, add it so
   training is recoverable if Spark loses power or OOMs mid-run.

3. **Category imbalance strategy** — augmenting to 3,000/cat may still leave
   `equation_symbolic` (1 example) and `equation_numeric_guess` (160) under-represented.
   If the augmenter exists for these, include them.

4. **Learning rate** — running warmstarted from a 0.53–0.56 adapter at `lr=2e-4` may
   overwrite gains. Start at `lr=1e-4` and watch loss trajectory.

## Risks

| Risk | Mitigation |
|---|---|
| Augmenter requires seed problems (not standalone) | Use competition `data/train.csv` as seeds; augmenters may just vary parameters |
| `train_v9_sft.py` OOMs on Spark at seq=8192 | Fall back to seq=4096 (same as Kaggle runs) |
| Generated data is too similar to existing corpus | Add `--seed` variation to augmenters; or accept — more diverse examples still help |
| run7 doesn't complete before Spark run | Warmstart from run4 (0.56) instead |
