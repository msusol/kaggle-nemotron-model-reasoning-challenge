## LR Schedule — Linear Decay

### What it is

The learning rate starts at `lr=2e-4` and decreases **linearly** to exactly 0 over all
948 training steps:

```
LR(step) = 0.0002 × (1 − step / 948)
```

| Step | LR | Phase |
|---|---|---|
| 0 | 0.000200 | Aggressive — structural learning |
| 100 | 0.000179 | |
| 200 | 0.000158 | |
| 440 | 0.000107 | Refining |
| 600 | 0.000073 | |
| 800 | 0.000031 | Locking in |
| 948 | 0.000000 | Zero — no more updates |

### Why linear, not cosine

The huikang 0.87 pipeline uses `StepLinearDecayLRSchedule` (from `lr_schedule.py` in
the nemotron-master snapshot). The key difference vs cosine:

| Schedule | Early LR | Late LR | Behaviour |
|---|---|---|---|
| **Cosine** (v0.4-r1, r2) | Slow decay | Fast decay near end | Cautious early, aggressive late |
| **Linear** (v0.4-r3, huikang) | Steeper early | Gentle near end | Commits quickly, refines gently |

For a single-epoch run over clean, deterministic data (the huikang corpus), linear decay
is more efficient: the model commits to the data distribution early and stabilises late,
rather than making large updates at the end when it has already seen all examples once.

### How to read LR in the training log

Each logged line includes `learning_rate`. Divide by 0.0002 (the starting LR) and
subtract from 1 to get the fraction of training completed:

```
step_fraction ≈ 1 − (current_lr / 0.0002)
e.g. lr=0.0001237 → 1 − (0.0001237/0.0002) = 0.382 → ~38% through training
```

This is more reliable than the `epoch` field when grad accumulation is in play.

## v0.4-r1 and r2 Loss Curves

Both r1 and r2 used cosine decay with the system prompt bug (r1: train/infer mismatch;
r2: system prompt contradicted augmenter category training data). Both finished at
train loss ≈ 0.221 and Kaggle scores of 0.49 / 0.50.

```
r1/r2 loss (every ~100 steps, approximate):
Step 100: ~0.35
Step 300: ~0.25
Step 500: ~0.24
Step 700: ~0.23
Step 948: ~0.221  (final)
```

Token accuracy at eval: 94.27% (r1), 94.57% (r2). High token accuracy with low Kaggle
score is the signature of the system prompt contradiction — the model learned the
training distribution correctly but that distribution was wrong for inference.

### Key observations

- **Faster initial drop** than r1/r2: below 0.22 by step 80 vs step 300+ in prior runs.
  Likely because empty system removes contradictory training signal for augmenter categories.
- **Below r1/r2 final loss at step 140** (~15% through training). Suggests the fixed
  data is meaningfully easier for the model to fit.
- **Noise band**: 0.17–0.22 from step 140 onwards. Normal for batch_size=1; individual
  batches dominate each step loss. The underlying level is consistently lower than r1/r2.
- **LR at step 440**: 0.000120 (40% of starting LR spent). Second half of training will
  tighten the loss as LR falls toward zero.

### Expected completion

- Steps remaining: ~510 (from step 440)
- Step time: ~57s
- ETA: ~8 hours from step 440

Expected final train loss: **~0.15–0.18** based on trajectory.
